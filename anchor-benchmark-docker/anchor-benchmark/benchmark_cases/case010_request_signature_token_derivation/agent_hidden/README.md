# case010_request_signature_token_derivation -- maintainer notes (agent_hidden)

This directory holds the private maintainer material for the case. The participating agent never sees it;
it only sees `../agent_visible/` (`task.json` + `captures/`).

## What the case is
A local two-step manifest delivery request signer. The page collects a carrier route, priority band,
delivery window and manifest ID, takes an integrity-binding mode, requires a manifest snapshot first, and on
Snapshot manifest then Issue seal prints an object to the browser console under action `media.sign`. The
observable target is that object's `req_sig` field: a deterministic `sig_` signature token derived from the
delivery controls, run-time transit state and shadow lanes via a keyed `Math.imul`/xor/rotate digest
(anchored by the constant `0x27d4eb2d`).

## Anchor (private)
- source_function `deriveRequestSignatureToken` in `src/z0/k7/q3/t9.js`: the orchestrator that composes the
  canonical request source, materializes the signing bytes and formats the `sig_` token. It is the
  shallowest target-specific function on the chain; its immediate caller is the generic forwarding closure
  `r` returned by the exported factory `u(config)` (the live instance is bound to slot 29).
- It is NOT `formatSignatureToken` (a nested 0.7 helper that builds the literal token string but is invoked
  by the anchor), NOT the factory `u` / closure `r` (0.2 wrappers), and NOT the sink `n0` (0.2).
- answer_function is the obfuscated bundle identifier (currently `_0x24c19d`); it is regenerated by
  `scripts/gen_oracle_spans.mjs` against the captured bundle, so do not hard-code it.
- Grading is by `captured_span` (offset/hash + complete enclosing function); `function_name` is a secondary
  key. `source_function` is a maintainer mapping only and is never the required agent answer.

## Layout
- `src/`: source (host page + `z0/**` business / decoy / vendor modules). In-task content; line-count
  floors apply here only (audit-spec section 3.2 / fix-plan M8).
- `scripts/build.mjs`: rollup then javascript-obfuscator (fixed `seed: 1010`, pinned deps + lockfile).
  Writes `dist/`, copies the bundle + page into `../agent_visible/captures/`, refreshes the capture
  manifest, then runs `gen_oracle_spans.mjs`.
- `scripts/gen_oracle_spans.mjs`: re-derives every `oracle.hidden.json` `captured_span` against the current
  captured bundle. All answer functions are module-private and therefore mangled, and >70% of strings are
  moved into a string array, so resolution is STRUCTURAL: numeric/hex fingerprints (`0x27d4eb2d`,
  `Uint8Array(0x12)`, base36 radix `0x24`, char-code arrays) plus the AST call graph. Writes
  `answer_function` + keeps `source_function`, and self-audits (no duplicate spans, anchor is the 3-param
  orchestrator calling the materializer and formatter).
- `scripts/verify.mjs`: case structure + runtime checks (drives the page in Chromium, confirms the
  `media.sign` / `req_sig` console object, sensitivity and decoy boundaries). It does NOT score agent answers.
- `scripts/grade_submission.mjs`: scores an agent submission against `oracle.hidden.json`.
- `oracle.hidden.json`: private gold standard (`primary_anchor` + 23-row `role_oracle`, dual-track names).
- `build_meta.hidden.json`: task contract, difficulty and analysis; mirrors `primary_anchor`.

## Frozen snapshot note
The committed `../agent_visible/captures` bundle and `oracle.hidden.json` are a frozen, runtime-verified
snapshot (`dist/` is kept byte-identical to it). The current bundle pre-dates the seed pinning; the
structural generator resolves against it correctly. A future `npm run build` will produce a deterministic
(seeded) bundle and the build -> sync-captures -> gen loop keeps `captures/` and `oracle.hidden.json` in
sync, so they never drift.

## Verify / grade loop
```
cd agent_hidden
npm ci            # pinned deps from package-lock.json
node scripts/gen_oracle_spans.mjs    # re-derive oracle spans against the captured bundle
npm run verify    # runtime + structure checks
npm run grade -- <submission.json>   # score an answer
```
